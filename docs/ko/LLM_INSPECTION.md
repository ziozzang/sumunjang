## 결정 요약

1. **비동기 집계 분석만 한다.** 어떤 모드에서도 LLM 호출은 접근 판정 경로에 없다.
   분석기는 개별 요청이 아니라 제한된 집계로 *대상*(주소, /24·/48, ASN 제안)을 평가한다.
2. **LLM 출력은 권고다.** 결과(판정·신뢰도·범주·근거)는 후보, ASN 제안, 허용 목록
   검토에 붙는 주석으로 저장되며 정책을 바꾸지 않는다. 이후 자동화는 결정적 관문을 거치는
   별도 검토 결정(L4 단계)이다.
3. LLM에 허용 목록 변경이나 ASN 전체 차단 권한을 **절대** 주지 않는다. ASN 제안에
   *주석을 달고* 허용 목록 검토를 *제안*할 수만 있다. 기존 사람 워크플로(2인 규칙, 명시적
   활성화)가 유일한 경로로 남는다.
4. **공격자가 제어하는 문자열은 데이터다.** 표시·이스케이프된 JSON facts 블록에만
   들어가고, 모델에는 도구가 없으며, 출력은 엄격한 스키마로 검증되고 제공된 fact ID만
   인용할 수 있다.
5. **기본 백엔드는 호스트의 Dorang 게이트웨이**이며 OpenAI 호환 인터페이스
   (`/v1/chat/completions`)를 쓰고 다른 호환 제공자로 바꿀 수 있다. 기본 동시 호출은
   최대 4개다(Dorang 공유 제공자의 실측 안전 구간은 *모든* 클라이언트 합계 8–10).
6. **별도 프로세스**(`sumunjang-analyst`)가 좁은 전용 자격(집계/explain 읽기, 주석
   쓰기)을 가진다. 제공자 장애, 프롬프트 오류, 분석기 침해가 정책을 바꿀 수 없다.

## 요청별(동기) 검사를 하지 않는 이유

| 항목 | 수문장 접근 판정 | Dorang 경유 LLM 호출 |
| --- | --- | --- |
| 지연 | p99 0.3–1.5ms(HTTP), HGD1 1ms 미만([성능](PERFORMANCE.md)) | 중앙값 1.2–2.6초, 이상치 약 16초(2026-10-16 실측) |
| 처리량 | 초당 100,000건 이상(TCP 최대 647k/s 측정) | 동시 8–10에서 초당 약 4건, 12–16 이상에서 차단기 열림 |
| 장애 | 한강 정책에 따라 100ms 내 fail-deny/fail-allow | 30–60초간 429/503 "out of service", 다른 클라이언트와 공유 |
| 비용(호출당 약 1k 토큰) | 없음 | 초당 1만 요청이면 하루 약 8,640억 토큰 |

동기 검사는 지연을 세 자릿수 배로 늘리고 처리량을 초당 몇 건으로 묶으며 모든 요청을 공유
외부 게이트웨이에 의존하게 만든다. 선택적 1–5초 판정 캐시도 도움이 안 된다. 키가 클라이언트
주소라 새 주소는 항상 미스이고 TTL이 LLM 호출 한 번보다 짧다. 따라서 판정 경로는 LLM을 기다리지
않고, LLM 결과는 검토된 결과물(차단, 제안)을 통해서만 접근 판정에 영향을 준다. 그 결과물은 판정
리비전을 바꾸므로 기존 캐시는 다른 정책 변경과 똑같이 1–5초 TTL 안에 수렴한다. *프롬프트
정책* 변경은 판정 캐시가 아니라 정책 버전 해시로 키를 둔 **분석 결과**를 무효화한다.

비동기 분석 예산 예: 시간당 대상 500개 × 약 1.5k 토큰 ≈ 하루 1,800만 토큰, 동시 호출 최대
4개(게이트웨이 안전 구간의 40% 이하).

## 구조

한강의 판정 이벤트(ADR 0019, 가명화) → 내보내기(exporter)의 집계/개수, 그리고 수문장(후보,
이력, explain, 존, ASN 카탈로그)이 `sumunjang-analyst`(별도 프로세스, 제한된 큐)에 입력된다.
분석기는 정책 트리거로 대상을 고르고 중복을 제거하며, 최소·마스킹·제한된 facts를 만들고,
LLM을 호출하고(Dorang `/v1/chat/completions`, 도구 없음), 출력을 검증(스키마, fact 참조,
관문)한 뒤 `POST /v1/llm/results`(주석만)로 기록한다. 콘솔은 "AI 제안"으로 표시한다.

분석기는 `HANGANG_GUARD_ANALYST_TOKEN`을 가진다: 후보·이력·explain/batch·존·ASN 카탈로그·
제안 읽기와 주석 쓰기. 수문장은 이 자격의 다른 모든 경로를 거부한다. LLM API 키
(`HANGANG_GUARD_LLM_API_KEY`)는 분석기에만 있다.

## 프롬프트 정책 스키마

프롬프트 정책은 변경 불가능한 버전 문서다(CAS 게시, 다른 정책처럼 감사, 편집은 새 버전).
필드: `id`, `version`, `goal`, `criteria`, `triggers`(후보 최소 점수, ASN 제안 상태, 허용
목록 검토 여부), `inputs`(보낼 필드 허용 목록), `output_schema`
(`sumunjang.llm.verdict.v1`), `model`(제공자, 이름, temperature 0, max_tokens), `budget`
(동시성, 시간당 호출, 하루 토큰), `result_ttl_secs`, `review`(표시 최소 신뢰도, 허용 권고
동작). 예시는 [영문 문서](../LLM_INSPECTION.md#prompt-policy-schema)에 있다.

`inputs`는 허용 목록이다. 나열하지 않은 필드는 절대 보내지 않는다. `headers` 기본값은 비어
있다. 헤더 이름은 명시적으로 추가할 수 있지만 `authorization`, `cookie`, `set-cookie`,
`proxy-authorization`과 token/secret/key 형태 이름의 값은 절대 보내지 않는다. 본문은 보내지
않는다.

**출력 스키마 `sumunjang.llm.verdict.v1`**(엄격, 추가 속성 없음): `subject`, `verdict`
(benign|suspicious|malicious|uncertain), `confidence`(0–1), `categories`(열거형),
`rationale`(500자 이하 일반 텍스트), `evidence`(fact ID 목록), `recommended_action`
(none|watch|propose_block_ip|propose_block_prefix|propose_asn_review|
suggest_allowlist_review).

검증: JSON 해석, 스키마, 열거형, `confidence` 범위, `subject`가 요청한 대상과 일치, 모든
`evidence`가 제공된 fact ID, 근거는 일반 텍스트(제어 문자·마크업·URL 제거, 언급된 주소나
ASN은 facts에 있어야 함), `recommended_action`은 정책이 허용한 값. 잘못된 출력은 사유와 함께
`invalid`로 저장하며 판정으로 표시하지 않는다.

## 입력: 최소화·마스킹·제한

facts는 수문장이나 내보내기가 이미 가진 데이터로만 만든다.

- 신호: 창 내 종류별 횟수와 점수, 메모리 이력 버킷.
- 판정 로그 집계(ADR 0019 내보내기): 경로 **템플릿**(원본 경로·쿼리 없음), 메서드 비율,
  상태 클래스, 요청 비율 통계, 거부 사유 — 개수만, 가명 대상 참조.
- 맥락: ASN, 국가, 존 ID, 일치 룰 ID, 기존 차단·허용 상태, 후보 점수·위험 단계.
- 마스킹: authorization/cookie 값은 수집하지 않는다. 쿼리 문자열과 본문은 제외한다. 템플릿
  안의 이메일, 긴 hex/base64 연속(토큰, 세션 ID), 6자리를 넘는 숫자 연속은 자리표시자로
  바꾼다. facts 안의 클라이언트 주소는 대상 자신이나 그 접두어뿐이며 다른 사용자의 주소는
  없다.
- 한도: 경로 템플릿 32개(각 128자), user-agent 분류 16개, 대상당 fact 64개, 호출당 facts
  8KiB, 배치당 대상 10개. 잘림은 facts에 명시한다(`"truncated": true`).

## 프롬프트 주입 방어

- 메시지 구조 고정: system 메시지 = 제품 머리말 + 정책 목표·기준(운영자 작성, 버전 관리),
  user 메시지 = JSON 객체 하나 `{"facts": [...], "subjects": [...],
  "instructions_reference": "<정책 id@버전>"}`. 공격자가 제어하는 문자열(경로 템플릿,
  user-agent 분류, 룰 설명)은 `"untrusted": true` 표시가 있는 JSON 문자열 값으로만
  들어가며 NFKC 정규화·제어 문자 제거·길이 제한을 거친다. 지시문과 이어 붙이지 않는다.
- system 프롬프트는 facts가 데이터이고 그 안의 지시를 무시하라고 말한다. 이것은 완화책일 뿐
  방어책은 구조다.
  - 도구·함수·검색·브라우징 없음(`tools: []`, `tool_choice` 없음).
  - 백엔드가 지원하면 JSON 스키마 `response_format`, 아니면 엄격한 해석+검증,
    temperature 0.
  - 출력은 검증되고, 제공되지 않은 대상이나 근거를 들일 수 없으며, 주석으로만 쓰인다.
  - 모델이 완전히 장악되어도 분석기 자격으로는 정책을 바꿀 수 없다.
- 모든 결과의 출처 기록: 정책 id/버전과 해시, 프롬프트 템플릿 해시, 제공자, 요청·보고된
  모델, 요청(facts) 해시, 응답 해시, 토큰 사용량, 지연, 시각.
- 평가 세트에 주입 사례(경로 템플릿·user agent 속 지시, 가짜 JSON 닫기, 역할 태그,
  "허용 목록 승인" 요청)를 넣고, 정책에 영향을 주는 이탈 0건을 합격 기준으로 한다.

## 제공자·모델·프롬프트 버전

- 백엔드: OpenAI 호환 chat completions. 기본 `--llm-base-url http://10.2.2.10:4000/v1`
  (호스트 Dorang, 호스트 포트 4000), `HANGANG_GUARD_LLM_API_KEY`, 모델은 정책에서(예:
  Dorang 카탈로그 이름 `zai:glm-5.3-flash`). 다른 호환 게이트웨이로 바꿀 수 있으며 호스트
  밖은 HTTPS 필수.
- 배포별 모델 허용 목록. 다른 모델을 지정한 정책은 거부.
- 결과마다 정책 버전, 템플릿 해시, 요청/보고 모델, 제공자를 기록한다. 서로 다른 버전의
  결과는 지표에서 섞지 않으며 모델이나 정책을 바꾸면 새 shadow 비교를 시작한다.

## 예산·시간 제한·장애

- 동시성: 정책별 `max_concurrency`(기본 2), 전체 상한 4. 게이트웨이의 제공자 한도는 호스트의
  다른 클라이언트와 공유한다(실측 안전 구간 8–10, 12 이상이면 모두에게 차단기가 열림). 수문장은
  작고 얌전한 테넌트여야 한다.
- 비율/비용: 정책별·전체 시간당 호출 수와 하루 토큰 수. 소진되면 큐를 멈추고 콘솔에 "예산
  소진"을 표시한다.
- 시간 제한: 호출당 20초, 검증 포함 배치당 30초.
- 차단기: 연속 실패 3회, `503 out of service` 또는 429에서 열림, 60초 뒤 반개방 시험
  (Dorang은 30–60초 안에 회복).
- 재시도: 최대 1회, 전송 오류만, 지터 포함. 4xx나 검증 실패에는 재시도하지 않는다.
- 중복 제거: 키 = (정책 버전 해시, 대상 참조, facts 해시). 같은 작업은 만료 전까지 저장된
  결과를 재사용한다.
- 만료: 결과는 `result_ttl_secs`(기본 1시간, 최대 24시간) 후 만료되고 30일 후 삭제한다. 정책
  게시는 이전 버전 결과를 표시에서 무효화한다(shadow 통계용으로는 보관).
- 큐: 제한됨(기본 대상 1,000개, 가장 오래된 것부터 버리고 셈).

## 결과·관문·권한

| 단계 | LLM 출력이 할 수 있는 것 | 절대 불가 |
| --- | --- | --- |
| L1–L3 | 후보·ASN 제안에 주석, 제안 문안 초안, 허용 목록 검토 제안 목록 | 제안 생성/승인/활성화, 허용 목록·룰·차단·모드 변경 |
| L4(별도 ADR) | 결정적 관문을 통과한 *정확한 IP의 임시* 차단만 | 허용 목록 변경, 접두어/ASN 차단, 영구 차단 |

L4 자동화의 결정적 관문(모두 필요): 주소가 이미 근거 임계값으로 승인 가능, 검토된 사례 500건
이상에서 shadow 정밀도 0.98 이상인 정책에서 신뢰도 0.9 이상의 `malicious`, 허용 목록·보호
존·제외 ASN에 속하지 않음, 차단 TTL은 정책 차단 TTL 이하, 시간당 자동 차단 상한, 집행 모드,
즉시 되돌림 스위치. 관문은 프롬프트가 아니라 코드다.

허용 목록(5단계): 분석기는 근거와 함께 `suggest_allowlist_review`를 낼 수 있다(예: 무해한
패턴의 모니터링·회사 출구 주소). 콘솔은 이를 허용 목록 편집기 옆에 보여 주고, 사람이 일반
CAS+감사 경로로 항목을 추가한다. ASN 제안: 분석기는 검토 화면에 보이는 `llm` 주석(판정 로그
집계 `decision_log`와 별도)을 붙이며 승인 규칙은 바뀌지 않는다.

## Shadow 평가와 되돌림

- 모든 결과를 이후 사람의 결과(후보 승인/기각, 제안 승인/거절, 오탐으로 제거된 차단)와
  비교한다. 정책 버전별 지표: 판정별 정밀도/재현율, 보정(calibration), 일치도, 잘못된 출력
  비율, 비용, 지연.
- 되돌림: 정책은 변경 불가능한 버전이다. 이전 버전 활성화나 전체 비활성 스위치는 다음 배치부터
  적용된다. 특정 버전의 결과를 숨길 수 있고, 차단기와 예산이 잘못된 모델의 피해를 제한한다.

## 콘솔 표시

네트워크 → 위협 대기열과 IP 화면은 판정과 분명히 구분되는 "AI 제안" 칩(판정, 신뢰도, 범주)과
근거, 인용 facts, 정책/모델 버전, 비용·지연, 검토 상태를 보여 준다. 정책 → 검사 화면에서
프롬프트 정책을 편집한다(스키마 양식, 검증, 평가 세트 시험 실행과 지표, 사유와 함께 게시).
ASN 제안 화면은 영향 분석 옆에 LLM 주석을 보여 준다. 예산·차단기·큐 상태는 시스템 화면에
나온다. 모든 문자열은 메시지 키(EN/KO)를 쓰고 모델 텍스트는 일반 텍스트로만 렌더링한다.

## 평가 데이터 세트

라벨이 있는 대상 facts의 재현 가능한 버전별 JSONL 픽스처:

- 무해: 검색 크롤러, 가동 감시, CI 러너, 회사 NAT 출구, 이동통신 CGNAT, 재시도하는 API
  클라이언트.
- 공격: 경로 탐색 스캐너, 크리덴셜 스터핑, 허니팟 접근, 저속 스캔, 분산 /24 캠페인.
- 적대적: 템플릿/user agent 속 주입 문자열, 오해를 부르는 ASN/국가, 과대·잘린 facts,
  유니코드 혼동 문자.
- 가명화된 집계와 합성 생성으로 만들며 원본 로그는 쓰지 않는다.

지표와 기준: 스키마 유효 99.5% 이상, 주입 저항 100%(스키마 밖 동작·제공되지 않은 근거·주입
문구로 인한 허용 목록 제안 없음), 범주별 정밀도/재현율을 신뢰 구간과 함께 보고, 모델별 p95
지연과 대상 1,000개당 비용 보고.

## API(계획)

- `GET/POST /v1/llm/policies`(CAS 게시, 사유, 감사), `POST /v1/llm/policies/{id}/dry-run`
- `POST /v1/llm/results`(분석기 자격, 검증된 주석), `POST /v1/llm/results/query`(필터, 커서)
- `GET /v1/llm/status`(큐, 예산, 차단기, 최근 오류)
- 지표: `sumunjang_llm_calls_total{result}`, `sumunjang_llm_tokens_total{kind}`,
  `sumunjang_llm_latency_seconds`, `sumunjang_llm_queue_depth`,
  `sumunjang_llm_breaker_open`, `sumunjang_llm_invalid_outputs_total` — 대상이나 모델
  텍스트는 라벨로 쓰지 않는다.

## 단계 계획과 합격 기준

| 단계 | 산출물 | 합격 기준 |
| --- | --- | --- |
| L0 | 이 설계, 출력 스키마, 평가 데이터 세트 v1 | 설계 검토 완료, 주입 사례 50개 이상을 포함한 라벨 대상 300개 이상 |
| L1 | Dorang을 쓰는 데이터 세트 대상 오프라인 평가 CLI(운영 데이터 없음) | 스키마 유효 99.5% 이상, 주입 저항 100%, 픽스처로 재현 가능한 지표 보고서 |
| L2 | 실시간 집계에 대한 `sumunjang-analyst` shadow, 주석과 콘솔 표시, 예산·차단기·지표 | 접근 경로 의존 없음(게이트웨이 장애에도 지연 불변), 예산 준수, 분석기 자격으로 정책 변경 불가(테스트) |
| L3 | 보조 워크플로: ASN 제안 주석, 허용 목록 검토 제안, 제안 초안 | 모든 정책 변경은 여전히 기존 CAS/감사/2인 규칙을 거침, 버전별 shadow 정밀도 대시보드 |
| L4 | 선택적 관문 기반 정확한 IP 임시 자동 차단(별도 ADR) | 관문은 코드, 검토 사례 500건 이상에서 shadow 정밀도 0.98 이상, 상한과 중지 스위치 검증 |

## 검토한 대안

- 요청별 동기 LLM 검사: 거부(지연, 처리량, 가용성. 위 표 참고).
- 수문장 API 도구 권한을 가진 LLM: 거부(주입이 권한을 얻게 됨).
- 작은 로컬 분류기/임베딩 우선: 보완적. L2 이후 LLM 호출 전 대상 선별에 쓸 수 있다.
- LLM 없음: 기본값으로 남는다. 분석기는 선택 사항이며 설정하지 않으면 비활성이다.

## 열린 질문

1. 엄격한 개인정보 프로필에서 내보내기(ADR 0019)가 대상별 템플릿 히스토그램을 제공하는지.
2. Dorang 테넌트 분리: 수문장 전용 가상 키/할당량 대 제공자 풀 공유.
3. 근거 텍스트 보존 기간(30일 제안)과 지역 규정.
4. temperature 0에서 한국어·영어 근거로 수용 가능한 정밀도를 내는 모델 계열.
